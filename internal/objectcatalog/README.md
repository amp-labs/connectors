# Object Catalog

The `objectcatalog` package loads canonical object metadata from a static JSON file and exposes it to connector implementations.
A catalog is usually defined in the connector's internal `metadata` package:

```go
var Catalog = objectcatalog.MustLoad(objectMetadataFile)
```

The source file may use either a `.json` or `.json.gz` extension.

## Producing `objectsMetadata.json`

The `objectsMetadata` file can be created manually, but it is most commonly generated from an OpenAPI document.

OpenAPI extraction scripts produce the object metadata and preserve each object's original URL path for use by the catalog.
For details on writing an extraction script and generating the file, see the 
[OpenAPI Connector Discovery guide](https://github.com/amp-labs/connectors/blob/main/connectors/scripts/openapi/internal/api/README.md).

## Purpose

The catalog is the starting point for the connector's `ListObjectMetadata` implementation and provides the necessary API paths for `Read` operations.

### Implementing `ListObjectMetadata`

In most connectors, the metadata loaded from `objectsMetadata.json` is complete and can be returned directly:

```go
func (c *Connector) ListObjectMetadata(
    ctx context.Context,
    objectNames []string,
) (*common.ListObjectMetadataResult, error) {
    return metadata.Catalog.SelectResult(objectNames)
}
```

### Getting started on `Read`

The catalog also stores each object's original URL path. Connector implementations can retrieve it with:

```go
path, err := metadata.Catalog.ReadPath(objectName)
```

This path, combined with information from `endpoints.json` (also generated by the script), provides the foundation for the `Read` implementation. For example, Stripe's `Read` implementation uses the catalog path along with provider-specific artifacts like `expandableFields.json`.

## Selecting objects

Use `Select` or `SelectResult` to retrieve metadata for specific objects:

```go
result, err := metadata.Catalog.SelectResult(objectNames)
```

`SelectResult` returns the result expected by `ListObjectMetadata`,
including metadata for supported objects and per-object errors for objects that could not be selected.

An empty object list returns an error. An unknown object returns `common.ErrObjectNotSupported`.

## Enriching metadata

Some connectors need to add fields from custom objects, provider endpoints, or other dynamic sources.
Use `Select` when the selected metadata needs to be modified before it is returned:

```go
selection, err := metadata.Catalog.Select(objectNames)
if err != nil {
    return nil, err
}

selection.AddField(
    "accounts",
    "externalStatus",
    common.FieldMetadata{
        DisplayName: "External Status",
    },
)

return selection.Result(), nil
```

`Selection` is request-scoped and mutable. Changes made to a selection do not modify the catalog.
This allows the catalog to remain immutable while individual connector requests enrich the metadata when necessary.

`AddField` returns `false` when the object was not selected.

## Reading object paths

`ReadPath` returns the canonical path stored for an object:

```go
path, err := metadata.Catalog.ReadPath("accounts")
```

The path is intended for constructing Read URLs. Paths for Write, Delete, Subscribe,
or other operations may require separate connector-specific handling when they differ from the Read path.

## Catalog immutability

`Catalog` is immutable after construction. `Object` returns a detached copy of an object's metadata,
including copied field metadata and slices. Callers can modify the returned metadata without changing the catalog.

`Select` also creates request-scoped metadata that can be enriched independently of the catalog.

## Static metadata format

The catalog is loaded from the generated object metadata file.
A catalog entry contains the object metadata served by `ListObjectMetadata` and the original object path used by `ReadPath`:

```json
{
  "accounts": {
    "displayName": "Accounts",
    "fields": {
      "id": {
        "displayName": "ID"
      }
    },
    "path": "/api/accounts"
  }
}
```

The exact object and field metadata depends on the connector's OpenAPI extraction and any subsequent transformations.
